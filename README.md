# LyricsTag

**Русский** | [English](README.en.md)

Документация v1.4 (lyrics_tag.py v6, плагин lyrics_tag_pp.py v3)

Автоматически добавляет **синхронный текст песни** (караоке-строки) в теги скачанных треков. Работает прямо на Android, без ПК: YTDLnis скачал трек - текст уже в файле, плеер показывает его по ходу песни.

Проверено на Poweramp. Форматы opus и mp3 (320 кбит/с) проверены на устройстве: текст, теги, обложка и сортировка по папкам работают.

Работает вместе с [YTDLnis](https://github.com/deniscerri/ytdlnis) (Android-оболочка для yt-dlp) и не требует ПК или root.

## Как это работает

1. YTDLnis качает аудио через yt-dlp.
2. После скачивания yt-dlp вызывает плагин LyricsTag (постпроцессор `after_move`).
3. Плагин запускает `lyrics_tag.py` прямо внутри процесса yt-dlp (без shell и subprocess).
4. Скрипт берёт текст:
   - **YouTube Music** через библиотеку `ytmusicapi` (основной источник, сначала берётся videoId из тега `purl` или из имени файла `[id]`; если по нему нет синхронного текста или id неизвестен, выполняется поиск, результаты которого проверяются на совпадение названия и исполнителя);
   - **LRCLIB** (запасной, только если на YT Music нет синхронного текста или он не опрошен).
5. Текст записывается в теги файла.

Куда пишется текст:

| Формат | Куда |
|---|---|
| opus, ogg, flac | тег `LYRICS` (текст в формате LRC) |
| mp3 | `SYLT` (синхронный) + `USLT` (обычный) |
| m4a | тег `©lyr` |

Если в файле уже есть текст, он пропускается (перезапись только с `force=1` или `--force`).

## Что нужно

- Android с приложением **YTDLnis** (в нём должен быть встроенный терминал с Python и pip)
- Файловый менеджер
- Плеер, который умеет читать встроенный LRC-текст (проверен Poweramp)

Проверено на: YTDLnis 1.9.1.1 (arm64) со встроенным yt-dlp 2026.08.19, Python 3.14, ytmusicapi 1.12.3.

## Структура проекта

```
/storage/emulated/0/Documents/Scripts/LyricsTag/
  README.md
  README.en.md
  LICENSE
  lyrics_tag.py
  libs/                                  (сюда ставится ytmusicapi, в репозитории её нет)
  yt_dlp_plugins/postprocessor/lyrics_tag_pp.py
```

Важно:
- имена папок `yt_dlp_plugins` и `postprocessor` менять нельзя, иначе yt-dlp не найдёт плагин;
- файлы `__init__.py` в них добавлять **не нужно**, они всё ломают;
- `lyrics_tag.py` плагин находит сам (путь вычисляется от места плагина), а `libs` скрипт подключает сам, если папка лежит рядом с ним.

## Установка

**1. Скопируй папку проекта**

Скачай репозиторий (кнопка "Code" - "Download ZIP"), распакуй и положи папку в `/storage/emulated/0/Documents/Scripts/` (файловым менеджером). Папку назови `LyricsTag` (после скачивания ZIP она называется иначе, например `LyricsTag-main`). Имя папки для yt-dlp неважно, но все пути в этой инструкции написаны для `LyricsTag`.

**2. Поставь ytmusicapi в терминале YTDLnis**

Открой в YTDLnis "Больше" - "Терминал" и вставь команду ниже. Именно в терминале YTDLnis, а не Termux: у них разные Python.

```bash
pip install --no-deps --target /sdcard/Documents/Scripts/LyricsTag/libs ytmusicapi
```

Библиотека ставится в папку проекта, а не в пакеты YTDLnis, потому что YTDLnis может сбросить свои пакеты (например, при обновлении), и вручную поставленное пропадёт. `--no-deps` нужен, чтобы не тащить копии `requests` и других библиотек: они уже есть в YTDLnis.

**3. Добавь шаблон команды в YTDLnis**

В YTDLnis открой "Больше" - "Шаблоны команд" и нажми "Новый шаблон". Заголовок любой (например, "Lyrics в теги"), в поле "Команда" вставь один из трёх шаблонов. Выбери по описанию, остальные можно использовать позже, заменив текст в шаблоне.

**Шаблон 1. Только текст песен.** Самый простой вариант: после скачивания в теги записывается синхронный текст.

```
-v --plugin-dirs "/sdcard/Documents/Scripts" --use-postprocessor "LyricsTag:when=after_move"
```

**Шаблон 2. Текст и сортировка по папкам.** То же, плюс трек автоматически переносится в папку с именем исполнителя (см. раздел "Сортировка по папкам исполнителей").

```
-v --plugin-dirs "/sdcard/Documents/Scripts" --use-postprocessor "LyricsTag:when=after_move;sort=1"
```

**Шаблон 3. Текст, сортировка и чистые имена исполнителей.** То же, плюс в имени файла и теге остаётся только первый исполнитель: убирает из `artist` авторов текста и продюсеров, которые YouTube Music добавляет через запятую (например, `Artist, Songwriter Name` превращается в `Artist`). Минус: настоящие дуэты (`A, B`) тоже станут `A` (подробнее в "Частые проблемы").

```
-v --plugin-dirs "/sdcard/Documents/Scripts" --parse-metadata "%(uploader)s:^(?P<uploader>.*?)(?:(?=,\s+)|$)" --parse-metadata "%(uploader)s:%(artist)s" --use-postprocessor "LyricsTag:when=after_move;sort=1"
```

Ниже включи переключатель "Дополнительная команда" и поставь галочку "Аудио" (галочку "Видео" не нужно). Остальное не трогай, нажми "Сохранить" (при правке готового шаблона кнопка называется "Обновить"). Теперь команда будет добавляться ко всем загрузкам аудио.

Названия пунктов даны для русской версии YTDLnis, в других версиях они могут отличаться.

Путь в `--plugin-dirs` - это папка, внутри которой лежит `LyricsTag` (то есть `Scripts`, а не сам `LyricsTag`).

## Проверка

Скачай один трек и открой лог: "Больше" - "Журналы". Нужны две вещи.

В начале лога:

```
[debug] Post-Processor Plugins: LyricsTagPP
```

В конце лога:

```
[LyricsTag] <имя файла>
[LyricsTag]   YT Music: синхронный текст (<videoId>)
[LyricsTag]   записано: синхронный текст
```

## mp3 и качество

YouTube отдаёт только Opus и AAC, готового mp3 у него нет. Когда в YTDLnis выбран контейнер mp3, приложение скачивает исходный поток и конвертирует его через ffmpeg (`--audio-format mp3`). Конвертация проходит до плагина, поэтому плагин получает уже готовый mp3 и пишет в него текст (`SYLT` + `USLT`). Теги и обложка сохраняются.

Битрейт mp3 задаётся отдельно. В карточке загрузки, в блоке "Настройка аудио", есть кнопка "Битрейт" (строка кнопок может быть обрезана справа, прокрути её). Выбери 320 kbps. Если оставить значение по умолчанию, YTDLnis не передаёт `--audio-quality`, и ffmpeg кодирует mp3 с собственным битрейтом по умолчанию. По размеру файла это около 128 кбит/с, звук получается заметно хуже исходного Opus.

То же самое можно задать командой в шаблоне (`--audio-quality 0` даёт VBR V0, около 245 кбит/с; `--audio-quality 320K` даёт CBR 320).

Opus в mp3 - это пережатие lossy в lossy, поэтому mp3 даже на 320 кбит/с не лучше исходника, а файл больше (на проверенном треке 11,0 МБ против 8,8 МБ у opus). Выбирай mp3, только если плеер или устройство не читает opus.

Проверено на устройстве (YTDLnis 1.9.1.1): mp3 320 кбит/с CBR, 48 кГц, по одному `SYLT` (синхронный текст) и `USLT` (обычный), обложка и теги на месте, сортировка по папкам работает. Мелочи, на которые можно наткнуться, к плагину не относятся: `COMM:ID3v1 Comment` с обрезанной ссылкой (ID3v1 ограничен 30 байтами, его пишет yt-dlp) и пустые номера трека и диска (yt-dlp их не передаёт).

## Параметры плагина

Параметры добавляются после `when=after_move` через `;`:

```
--use-postprocessor "LyricsTag:when=after_move;sidecar=1;lrc_in_uslt=1"
```

| Параметр | Что делает |
|---|---|
| `force=1` | перезаписать уже имеющийся текст |
| `sidecar=1` | дополнительно сохранить `.lrc` рядом с файлом |
| `lrc_in_uslt=1` | mp3: класть LRC-текст в `USLT` (для плееров, не читающих `SYLT`) |
| `sort=1` | после записи текста переложить трек в подпапку основного исполнителя (см. раздел ниже) |
| `script=/путь/к/lyrics_tag.py` | использовать скрипт из другого места |

## Ручной запуск (для уже скачанных треков)

В терминале YTDLnis ("Больше" - "Терминал"):

```bash
python /sdcard/Documents/Scripts/LyricsTag/lyrics_tag.py "/storage/emulated/0/Music/YT Music"
```

Можно указывать папку или отдельные файлы. Ключи: `--force`, `--sidecar`, `--lrc-in-uslt`, `--no-yt` (не использовать YT Music, только LRCLIB), `--sort` (после текста разложить по папкам исполнителей), `--sort-only` (только разложить по папкам, текст не трогать, интернет не нужен).

Работает и в Termux, если там поставлены `mutagen` и `ytmusicapi`:

```bash
pip install mutagen ytmusicapi
```

## Сортировка по папкам исполнителей

По умолчанию выключена. Трек перекладывается в подпапку с именем **основного исполнителя** (первого из списка в теге `artist`), `.lrc` рядом переезжает вместе с ним.

Как определяется основной исполнитель:
- `Artem Pivovarov, Klavdia Petrivna` - папка `Artem Pivovarov`
- `Artist feat. Other` - папка `Artist`
- `Some Band - Topic` - папка `Some Band`
- `Artist; Other` - папка `Artist`
- символы, запрещённые в именах папок, заменяются на `_` (`AC/DC` - папка `AC_DC`)
- если исполнитель не указан, трек остаётся на месте

Известное ограничение: список делится по запятой, поэтому `Tyler, The Creator` попадёт в папку `Tyler`.

Имя папки берётся из тега `artist`. Если в теге лишние имена (например, YouTube Music добавил автора текста или продюсера), в папку попадёт только первое, но в теге и в имени файла лишнее останется: это приходит из метаданных yt-dlp, а не из плагина. Как это убрать, см. "Частые проблемы".

**Автоматически после скачивания** (добавь `sort=1` в шаблон):

```
-v --plugin-dirs "/sdcard/Documents/Scripts" --use-postprocessor "LyricsTag:when=after_move;sort=1"
```

Папка исполнителя создаётся внутри папки, где плагин находит трек. Плагин сам обновляет путь к файлу в yt-dlp, поэтому YTDLnis видит трек уже в папке исполнителя (проверено на YTDLnis с yt-dlp 2026.08.19: "Расположение", "Открыть файл" и история загрузок работают). Работает ли это в других версиях, не проверялось: если у тебя не получится, убери `sort=1` и используй ручной запуск ниже.

**Вручную для уже скачанного** (в терминале YTDLnis):

```bash
python /sdcard/Documents/Scripts/LyricsTag/lyrics_tag.py "/storage/emulated/0/Music" --sort-only
```

Внутри указанной папки создаются подпапки исполнителей, а треки раскладываются по ним, в том числе те, что лежат в других подпапках. Для первого раза лучше указать небольшую папку с копией треков.

## Перенос на другой телефон

1. Скопируй папку `LyricsTag` в `Documents/Scripts/` на новом телефоне.
2. Повтори шаг 2 установки (библиотека в `libs`).
3. Повтори шаг 3 установки (шаблон в YTDLnis).

Если папка лежит в другом месте, поменяй путь в `--plugin-dirs` (он должен указывать на папку, содержащую `LyricsTag`).

## Частые проблемы

**В логе `No module named 'ytmusicapi'`**
Папка `libs` пропала или пустая. Повтори шаг 2 установки.

**В логе `LRCLIB: ... 503`**
Запасной сервис временно недоступен. Скрипт сам повторяет запрос до 3 раз.

**В логе `LRCLIB: трек не найден (404)` и `текст не найден`**
Для трека нет текста ни на YT Music, ни в LRCLIB. Так бывает у малоизвестных треков.

**В имени файла и теге исполнителя лишние имена (например, `Artist, Songwriter Name - song.opus`)**
YouTube Music отдаёт в список исполнителей не только артистов, но и авторов текста и продюсеров, а YTDLnis склеивает весь список через запятую. Плагин тут ни при чём. Чтобы оставить только первое имя, добавь в шаблон команды две опции yt-dlp перед `--use-postprocessor`:

```
-v --plugin-dirs "/sdcard/Documents/Scripts" --parse-metadata "%(uploader)s:^(?P<uploader>.*?)(?:(?=,\s+)|$)" --parse-metadata "%(uploader)s:%(artist)s" --use-postprocessor "LyricsTag:when=after_move;sort=1"
```

Первая опция обрезает исполнителя до первого имени (оно попадает в имя файла), вторая копирует его в тег `artist`. Проверено на одном треке на YTDLnis с yt-dlp 2026.08.19. Побочный эффект: настоящие дуэты (`A, B`) тоже станут `A`, как и `Tyler, The Creator` станет `Tyler`.

**mp3 звучит плохо**
Скорее всего, не выбран битрейт, и ffmpeg кодирует mp3 примерно на 128 кбит/с. Выбери кнопку "Битрейт" - 320 kbps (см. раздел "mp3 и качество").

**Строк `[LyricsTag]` в логе нет**
Плагин не подхватился. Проверь строку `Post-Processor Plugins:` в логе и структуру папок (раздел "Структура проекта"). Частые причины: неверный путь в `--plugin-dirs`, лишний `__init__.py`.

**Текст не появился, хотя в логе "уже есть текст, пропуск"**
В файле уже есть текст. Используй `force=1`.

## Ограничения

- `ytmusicapi` использует неофициальный внутренний API YouTube Music и может перестать работать при изменениях со стороны Google.
- Проверено на одном устройстве и одной версии YTDLnis, на форматах opus и mp3. Запись в m4a и flac реализована и проверена только на тестовых файлах на ПК, на устройстве с реальными треками не проверялась.
- Не гарантируется, что у всех треков есть синхронный текст.
- Тексты песен принадлежат их правообладателям. Скрипт только записывает в теги твоих личных файлов то, что отдают YouTube Music и LRCLIB, и сам тексты нигде не хранит и не распространяет.
- Проект не связан с YouTube, Google, YTDLnis, yt-dlp или LRCLIB.
